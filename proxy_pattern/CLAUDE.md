# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

LiteLLM proxy acting as a security gateway in front of cloud LLM providers. Three containers behind a single host-exposed port: **LiteLLM proxy** (`:4000`) + **PostgreSQL 16** (key/team/spend storage, SSL-only) + **Redis 7** (cache + rate-limit state). The proxy front-ends multiple providers (Mistral, OpenAI, Anthropic, Azure, …) through one OpenAI-compatible API and adds budgets, rate limits, audit logs, virtual keys, and Prometheus metrics.

## Bootstrap (first run on a fresh checkout)

```bash
# 1. Generate self-signed Postgres SSL certs (writes to ./certs/)
bash scripts/postgres_ssl.sh

# 2. Create your local env file from the template
cp .env.template .env
# then edit .env and fill in real API keys

# 3. Bring everything up
docker compose up -d

# 4. Smoke test (host-side curl)
bash test.sh                                  # or: ./test.sh after `chmod +x test.sh`
# OR (in-network curl):
docker compose --profile tools run --rm test
```

Admin UI lives at `http://localhost:4000/ui`, Prometheus at `/metrics`, health at `/health`.

## Architecture

The litellm service uses `ghcr.io/berriai/litellm:main-latest` **directly** — there is no local Dockerfile and no custom image build. `litellm_config.yaml` is bind-mounted read-only at `/app/config.yaml`. To change models, providers, routing, caching, rate-limit settings, etc., edit `litellm_config.yaml` and restart the container; **do not** rebuild anything.

```
host:4000  ──►  litellm:4000  ──►  postgres:5432 (SSL only)
                              └─►  redis:6379
```

Networking: single `litellm_network` bridge (subnet `172.28.0.0/16`, bridge name `litellm0`). Only the litellm port is published to the host; postgres and redis are network-internal.

Each container is hardened: `cap_drop: ALL`, `no-new-privileges:true`, postgres and redis run `read_only: true` with `tmpfs` for `/tmp` and `/var/run/postgresql`. Resource caps are tuned for 12-core / 64 GB hosts (M2 Max in the original notes) — adjust the `deploy.resources` blocks if running elsewhere.

## File map

| File | Role |
|---|---|
| `docker-compose.yml` | Single source for all container wiring. No Dockerfile. |
| `litellm_config.yaml` | The proxy's runtime config — models, router, caching, security headers, rate limits. Mounted into the container as `/app/config.yaml:ro`. |
| `.env.template` | Canonical env-var schema. Workflow: `cp .env.template .env`. |
| `.env` | User-local secrets — gitignored. |
| `init-db.sql` | Postgres bootstrap: extensions (`uuid-ossp`, `pgcrypto`), `litellm` schema, audit-log table + trigger function, `ALTER SYSTEM` hardening. **Only runs once**, on volume initialization. See "Gotchas" below. |
| `certs/server.{crt,key}` | Self-signed certs for postgres SSL. Generated by `scripts/postgres_ssl.sh`. Not in git. |
| `scripts/postgres_ssl.sh` | Generate / rotate the postgres SSL pair. Cross-platform (macOS + Linux). Sets `chmod 600` on the key (postgres requires this). |
| `scripts/backup.sh` / `restore.sh` | `pg_dump` / `pg_restore` wrappers; load creds via `export $(cat .env ...)`. |
| `scripts/health_check.sh` | Composite multi-service health probe (postgres, redis, litellm). |
| `test.sh` | Host-side smoke test: health → mint virtual key → call `gpt-5-nano`. Ships without `+x` — invoke as `bash test.sh` or `chmod +x` first. |

The `test` service inside `docker-compose.yml` is functionally identical to `test.sh` but runs in-network. It's gated behind `profiles: [tools]`, so it doesn't start with bare `docker compose up`; invoke with `--profile tools run --rm test`.

## Gotchas (these have all bitten us — preserve the workarounds)

- **Postgres won't start without certs in `./certs/`.** The compose command is `postgres -c ssl=on -c ssl_cert_file=/postgres_certs/server.crt -c ssl_key_file=/postgres_certs/server.key`. If `./certs/` is empty (fresh clone), `bash scripts/postgres_ssl.sh` first. If `postgres_data` volume already has stale `ssl = on` in its `postgresql.conf` but no certs, you'll see `FATAL: could not load server certificate file "server.crt"` — generate the certs or wipe the volume.

- **SSL key ownership mismatch.** Postgres rejects key files readable by anyone but the server user. The bind-mounted key is owned by the host user (typically uid 1000), but the container runs `user: postgres` (uid 70 on alpine). If you hit `private key file "server.key" has group or world access`, either remove `user: postgres` from the postgres service (runs as root inside the container) or `sudo chown 70:70 certs/server.key` on the host. `scripts/postgres_ssl.sh` prints both options.

- **`init-db.sql` runs only once.** The official postgres image only runs `/docker-entrypoint-initdb.d/*` files when initializing a fresh data dir. If you change `init-db.sql`, you must `docker compose down -v` (which destroys `postgres_data`) to re-trigger it. Otherwise the changes silently never apply.

- **Don't add `USER 1000:1000` to the litellm setup.** The upstream LiteLLM image bakes Prisma engine binary paths into `/root/.cache/...` at image-build time. Running as uid 1000 makes those paths unreadable, killing every uvicorn worker on startup with `prisma.engine.errors.NotConnectedError: Not connected to the query engine`. The hardening on this container is `cap_drop: ALL` + `no-new-privileges` — not a uid switch.

- **Healthcheck uses `python3` because Wolfi has no `wget` or `curl`.** The upstream LiteLLM image is built on Wolfi Linux, which doesn't ship `wget` or `curl`. The healthcheck reaches for `python3 -c "import urllib.request; …"` because that's what's actually present. Don't "simplify" it back to `wget`.

- **Compose `test` service calls `gpt-5-nano`, but `litellm_config.yaml` only has `mistral-small-latest` uncommented by default.** If you run `docker compose --profile tools run --rm test` without first uncommenting GPT model blocks in `litellm_config.yaml` (and setting `OPENAI_API_KEY` in `.env`), step 3 of the test fails. Edit the test's model name or uncomment the matching model in `litellm_config.yaml`.

- **`OPENAI_API_KEY` and `MISTRAL_API_KEY` are `:?` required.** Lines 85–86 of `docker-compose.yml` use `${VAR:?…}`. Compose will refuse to start if either is unset or empty. To work with only one provider, comment out the other line.

- **`LITELLM_SALT_KEY` cannot rotate.** It encrypts provider credentials stored in postgres. Changing it after first use makes all stored keys undecryptable. Set it once in `.env`, back it up.

- **Postgres data volume is named.** It survives `docker compose down`. To truly reset (e.g. to re-run `init-db.sql` or change `POSTGRES_PASSWORD` after first init), use `docker compose down -v`.

## Where to make which kind of change

- **Add a provider / model** → `litellm_config.yaml` (`model_list:`). The corresponding `*_API_KEY` env var must also be passed through in `docker-compose.yml`'s litellm `environment:` block and present in `.env`.
- **Change a secret** → `.env` only. `docker-compose.yml` already references it.
- **Add a new env var** → add to `.env.template`, add the line in `.env`, reference as `${VAR:-default}` in `docker-compose.yml`.
- **Change cache TTL, rate limits, security headers, master budget** → `litellm_config.yaml` (`general_settings:` / `litellm_settings:`).
- **Change Postgres schema bootstrap** → `init-db.sql` + `docker compose down -v` to re-run.
- **Rotate SSL certs** → `bash scripts/postgres_ssl.sh` (overwrites with prompt), then `docker compose restart postgres`.

## Common operations

```bash
docker compose ps                                # status / health
docker compose logs -f litellm                   # tail proxy logs
docker compose exec postgres psql -U litellm_user -d litellm
bash scripts/health_check.sh                     # composite probe
bash scripts/backup.sh                           # pg_dump → ./backups/
docker compose down                              # stop, keep volumes
docker compose down -v                           # stop, NUKE volumes (forces re-init)
```
